1. Purpose and Scope

This document describes the functional and technical specifications of the NQF Learner Placement Assessment Platform — a purpose-built web application for administering, marking, and reporting on NQF learner placement assessments in supervised computer-lab environments.

The platform replaces manual paper-based assessment administration with a structured digital workflow covering the full assessment lifecycle: session creation, learner self-registration, timed assessment delivery, automated and manual marking, working sheet management, and results reporting.

3. Functional Specification

3.1 Assessment Templates and Questions

  • Multiple assessment templates supported; each template contains one or more ordered sections.
  • Questions belong to a section and support the following types: free text, fill-in-the-blanks, matching, multiple choice, sentence construction, and keyword-answer.
  • Questions carry a maximum marks value and an optional answer key for auto-marking.
  • Each question can be toggled active/inactive by an administrator; inactive questions are hidden from learners and excluded from marking.
  • Marking guidance notes can be attached to any question for assessor reference.

3.2 Session Management

  • Assessors create timed sessions linked to a template with a configurable seat limit.
  • Sessions expire 2 hours after creation.
  • A unique session code is generated; learners join by entering the code at the join URL.
  • The session monitor displays real-time seat status (in progress / submitted / abandoned) with a progress bar per learner, refreshing every 30 seconds.
  • Browser notifications alert the assessor on each learner submission and when all seats are filled.
  • Printable working sheets (pre-filled with learner name and attempt code) can be printed per seat from the session monitor.

3.3 Assessment Delivery

  • Each section is independently timed at 45 minutes. A visible countdown runs throughout.
  • On section timeout, the learner is automatically advanced to the next section. Unanswered questions in the timed-out section receive zero marks.
  • After completing all sections, learners may review their answers (90 seconds per question) or submit immediately.
  • The platform enforces a 2-hour hard cap per attempt; attempts not submitted within this window are automatically finalised.
  • Learner progress is persisted per question; browser refresh or accidental navigation does not lose responses.

3.4 Auto-Marking

Answer key typeBehaviour
Numeric / text matchAnswer detected in response text using normalised matching (handles comma decimals, currency symbols, unit noise)
Working evidenceExpected calculation steps checked by keyword; partial marks awarded if answer correct but working absent; flagged for assessor review
Keyword answerRequired terms checked for presence; partial marks if some found; configurable flag-always for assessor override
Sentence constructionTarget word (with inflections) checked; minimum word count enforced; always flagged for review
Match / drag-dropEach target-word pair scored independently at configurable marks per match
Blank responseZero marks awarded, no review flag, regardless of question type
No answer keyQuestion left unscored; appears in assessor review queue for manual marking

3.5 Assessor Marking

  • The Review Queue lists all submitted attempts with at least one question requiring assessor input. A badge count in the navigation updates in real time.
  • The marking view presents a sidebar listing all markable questions with pending/done status indicators; assessors can navigate directly to any question by clicking it.
  • Questions are displayed one at a time showing the question prompt, learner's response, and a scoring form (rubric criteria or manual point entry).
  • Auto-marked scores are shown read-only alongside the question for context; the assessor can override any auto-mark.
  • Assessor notes can be entered per question and per rubric criterion.
  • A marking summary screen displays all questions with awarded marks before the assessor finalises the attempt.

3.6 Working Sheet Management

  • Printable working sheets are generated per attempt with ruled space for each numeracy question requiring shown working.
  • Assessors upload a scan or photograph (JPEG, PNG, WEBP, or PDF) from within the marking view.
  • Uploads replace any existing sheet for the attempt. The file is stored in the database and served back on demand.
  • The uploaded sheet is accessible as a View link from the marking view for assessor reference during marking.

3.7 Results and Reporting

  • Per-attempt results show total marks awarded, total available, and percentage.
  • NQF placement recommendations are computed from the marks profile across competency areas.
  • All attempt and score data is exportable to CSV.
  • Optional reporting dashboard and branded PDF executive reports are available as paid add-ons.
