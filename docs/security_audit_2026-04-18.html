HIGH

# Finding Location Status
H-1 ALLOWED_HOSTS = ["*"] — wildcard accepted in production. HTTP Host header attacks possible. Must be driven by an environment variable. config/settings.py:30 ✓ DONE
H-2 SECRET_KEY has a hardcoded fallback. os.environ.get("DJANGO_SECRET_KEY", "fallback-for-local-only") — if the env var is ever absent on Render, Django runs with a known key. All session and CSRF tokens become forgeable. config/settings.py:25 ✓ DONE
H-3 DEBUG defaults to True. os.environ.get("DEBUG", "True") == "True" — if the env var is missing, production runs in debug mode exposing full stack traces and all settings values. config/settings.py:28 ✓ DONE
H-4 No brute-force protection on login. Django's built-in login view has no rate limiting. django-axes or django-ratelimit is absent. An attacker can enumerate credentials without limit. requirements.txt, config/urls.py ✓ DONE
H-5 Learner views have no ownership check. attempt_question, attempt_submit, attempt_details, attempt_submitted, attempt_instructions all use get_object_or_404(Attempt, code=code) with no verification that the attempt belongs to the current browser session. Learner A can read and interact with Learner B's attempt by knowing the code. views.py:923–1090 ✓ DONE
H-6 Content-Disposition header injection. original_filename from the upload is stored as-is and inserted into the header inside double-quotes with no sanitisation. A filename containing " or \n can break the header or inject a new one. views.py:1517, 1538 ✓ DONE

MEDIUM

# Finding Location Status
M-1 No HTTPS security settings. SECURE_SSL_REDIRECT, SECURE_HSTS_SECONDS, SECURE_PROXY_SSL_HEADER, SESSION_COOKIE_SECURE, and CSRF_COOKIE_SECURE are all absent. Render terminates TLS at the edge; Django must be told it is behind a proxy or cookies travel insecurely. config/settings.py ✓ DONE
M-2 No Content-Security-Policy. django-csp is not installed and no CSP header is sent. XSS on any template would render arbitrary scripts without restriction. requirements.txt, config/settings.py ✓ DONE
M-3 No session lifetime configured. SESSION_COOKIE_AGE and SESSION_EXPIRE_AT_BROWSER_CLOSE are not set. Django default is 2 weeks. An exam-context app should expire sessions at browser close at minimum. config/settings.py ✓ DONE
M-4 No upload size limit. (RESOLVED) DATA_UPLOAD_MAX_MEMORY_SIZE and FILE_UPLOAD_MAX_MEMORY_SIZE are not set. A large scan from an assessor's phone could memory-exhaust the worker. config/settings.py ✓ DONE
M-5 File upload trusts browser content-type. uploaded_file.content_type is browser-supplied. An attacker can declare image/jpeg while uploading a malicious file. Magic byte validation via Pillow or python-magic is absent. views.py:1507 ✓ DONE
M-6 No custom 404/500 error pages. Django's defaults expose the framework name in debug mode and are generic outside it. Custom templates are required before production. templates/ ✓ DONE
M-7 /admin/ is at the default path. Automated scanners probe this path constantly. Moving it to an obscure URL reduces the automated attack surface. config/urls.py:5 ✓ DONE
M-8 No SECURE_REFERRER_POLICY. Not configured; the full URL is sent as Referer to any resource. Internal attempt codes could leak to third-party assets. config/settings.py ✓ DONE
M-9 No .env.example. No committed example file. A new developer has no hint of required variables, risking a local startup with missing or wrong values. Project root ✓ DONE
M-10 Superuser password set from env var in build.sh. DJANGO_SUPERUSER_PASSWORD flows through a shell command that may appear in Render build logs. Confirm it is marked Secret in the Render dashboard and does not surface in log output. build.sh:38–50 ✓ DONE
